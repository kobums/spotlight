# 창 관리 (Rectangle 대체) — 설계

2026-07-19 조사·설계. 사용 방법은 [features.md](features.md), 구현 노트는 [architecture.md](architecture.md) 참조.

## 조사 요약

[Rectangle](https://github.com/rxhanson/Rectangle)(Spectacle 후속, Swift 오픈소스)의 본질은
"**최전면 창의 프레임을 미리 정의된 위치로 변경**" 하나다. 전 기능이 손쉬운 사용 API 두 속성
(`kAXPositionAttribute`/`kAXSizeAttribute`) set으로 구현된다 — Spot이 힌트 모드에 이미 쓰는
권한·코드 기반과 동일해서 새 권한이 필요 없다.

Rectangle 기능 인벤토리: 절반(좌/우/상/하/중앙) · 1/3·2/3 (같은 키 반복 시 ½→⅔→⅓ 사이클) ·
코너 1/4 · 1/6·1/8·1/9 그리드 · 최대화/거의-최대화/높이만 · 중앙 정렬 · 디스플레이 간 이동 ·
복원(undo) · 크게/작게 · 스냅 영역(드래그).

## 채택 범위

| 채택 | 이유 |
|---|---|
| 절반·코너·최대화·중앙·복원 + ½→⅔→⅓ 사이클 | 실사용 빈도 최상위, 1단계 |
| 디스플레이 간 이동, 런처 명령(`창 왼쪽` 등) | 2단계 |
| 거의-최대화, 크게/작게 | 3단계 (폴리시) |

| 미채택 | 이유 |
|---|---|
| 스냅 영역 (드래그) | 마우스 기능 — "키보드 최대" 철학과 상충 |
| 1/6·1/8·1/9 그리드 | 개인용에서 사용 빈도 낮음, 키맵 복잡도만 증가 |
| 다른 Space로 이동 | 공개 API 없음 (Rectangle 본가도 미지원) |

## 설계: 창 모드

Rectangle 기본 단축키(⌃⌥+화살표)는 3키 조합이라 HHKB 제약(2키)에 걸린다.
대신 힌트/그리드/스크롤과 같은 **모드 방식**을 쓴다 — 진입 후 단일 키로 연속 조작:

```
⌃Space (힌트 모드) → "." → 창 모드
```

| 키 | 동작 |
|---|---|
| H / J / K / L | 좌 / 하 / 상 / 우 절반. **같은 키 반복 = ½ → ⅔ → ⅓ 사이클** |
| Y / U / B / N | 코너 1/4 (좌상 / 우상 / 좌하 / 우하 — 자판 위치 = 화면 위치) |
| M | 최대화 (메뉴바·Dock 제외 가용 영역) |
| C | 중앙 정렬 (크기 유지) |
| R | 복원 — 첫 스냅 이전 프레임으로 |
| Esc 또는 ⌃Space | 종료 |

- 모드가 유지되므로 "왼쪽 절반 → 한 번 더(⅔) → K(상단)"처럼 연속 조정 가능
- 다른 키는 모두 삼킨다 (스크롤 모드와 동일 패턴)
- 진입 키 "."는 한글 입력 상태와 무관 (";"·"/"와 같은 IME 투명 키)

## 구현 노트 — AX 창 이동의 함정 3개

Rectangle이 실제로 겪고 해결한 것들. 우리 구현도 동일하게 대응한다:

1. **`AXEnhancedUserInterface` 애니메이션 버그** — 이 플래그가 켜진 앱(Chrome 등)은 AX 창 이동이
   애니메이션되며 최종 위치가 어긋난다. Spot은 힌트 모드가 Electron 앱에 이 플래그를 직접 켜므로
   자기 발등 이슈: **이동 직전 플래그를 끄고, 이동 후 원상복구**한다.
   ([Mozilla 버그 1664992](https://bugzilla.mozilla.org/show_bug.cgi?id=1664992) 참조)
2. **클램핑과 적용 순서** — 앱이 최소/최대 크기로 클램프하거나 화면 경계에 걸린 이동이 어긋날 수 있다
   → position→size 순서로 **두 번** 적용.
3. **가용 영역과 멀티 디스플레이** — 화면 전체(`frame`)가 아니라 메뉴바·Dock을 뺀
   `NSScreen.visibleFrame` 기준. 대상 화면은 "창과 교집합이 가장 큰 화면"으로 판정.
   좌표 변환은 기존 `ScreenCoords` 재사용.

**복원 저장**: 창별로 첫 스냅 직전 프레임을 기억(AXUIElement를 CFEqual로 비교, 최근 20개 상한).
Spot 재시작 시 소실되는 휘발성 저장 — undo 용도로 충분.

## 전역 단축키 (Rectangle 호환)

사용자가 Rectangle에서 쓰던 단축키를 그대로 등록한다 — 근육 기억 유지가 목적.
창 모드와 같은 `WindowManager`를 호출하는 별도 진입 경로다.

| 단축키 | 동작 | | 단축키 | 동작 |
|---|---|---|---|---|
| ⌥⌘← / → / ↑ / ↓ | 좌/우/상/하 절반 | | ⌥⌘F | 최대화 |
| ⌃⌘← / → | 좌상/우상 코너 | | ⌃⌥⇧↑ | 높이 최대화 |
| ⌃⇧⌘← / → | 좌하/우하 코너 | | ⌃⌥⇧← / → | 작게 / 크게 (±30px) |
| ⌥⇧⌘← / → | 이전/다음 디스플레이 | | ⌥⌘C | 중앙 정렬 |
| | | | ⌃⌥⌫ | 복원 |

- 디스플레이 이동은 원본 화면 내 상대 위치·크기를 **비율로 유지**하며 이동
- 전역 단축키에서도 절반 액션의 ½→⅔→⅓ 사이클이 동일하게 동작

## 설정 창

메뉴바 → "설정…" (Rectangle 환경설정 대응, 스냅 영역은 미채택이라 없음):

- **키보드 단축키 탭**: 16개 액션 각각 레코더 — 칸 클릭 → 새 조합 입력(Esc 취소), ✕로 해제,
  "기본 단축키 복원" 버튼. 변경 즉시 핫키 재등록
- **설정 탭**: 반복 입력 시 크기 순환 분율(½·⅔·¾·¼·⅓ 체크), 창 사이 간격 슬라이더
- 저장: `~/Library/Application Support/Spot/window-settings.json` (`JSONFileStore` 디바운스)
  — 백업·이관은 파일 복사면 된다
- 간격 규칙: 화면 가장자리에 닿는 변은 gap, 창끼리 맞닿는 안쪽 변은 gap/2
  (사이클 일치 판정도 gap 적용된 후보와 비교)

## 컴포넌트

```
WindowManager            프레임 계산(사이클 판정 포함) + AX 적용 + 복원 저장
WindowModeController     하단 HUD + 키 입력 (ScrollModeController 패턴 재사용)
HintModeController       "." 진입 연결, ⌃Space 순환에 창 모드 종료 추가
WindowSettings(Store)    설정 모델·영속·변경 알림 (핫키 재등록 트리거)
SettingsWindowController 설정 창 (SwiftUI, 단축키 레코더 포함)
```
